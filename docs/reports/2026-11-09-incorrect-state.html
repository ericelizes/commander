Summary and top findings

"State missing" is not one bug. Two structural facts produce it:

  • No write path promises a holder. About thirty paths write beads. Exactly one, the close door in internal-close-objective (cmd/cmdr/door_checks.go:358-411), checks that the work it releases is still held. It runs on the client, against a snapshot that can lag, and it exempts the user, the owning Manager and an Operator closing its own work. cmdrd's own writes (settle, waits, live gates, unpark) skip the write door entirely (beads.SetDoorServer(true), internal/daemon/daemon.go:476).
  • "Held" has six definitions. The invariant (livedata.OpenBeadInvariant), the board's own line ordering, the diagram's unheld finding, StalledWork, the close door's UnheldAfter and the audit's open-bead-no-owner each decide it a little differently. Some writes pass one predicate and fail another, so a write the door accepts can still read wrong on the board.
Top findings (the first five are the ones asked for; the sixth came from the Manager's mail)
  1. A Manager's name is accepted as an owner, but it is not a durable holder. internal-set-objective --state in-progress --owner manager-x passes requireOwner and checkOwnerLive (door_checks.go:216-224 checks only operator-* and user). The invariant counts it only while that Manager is mid-turn (internal/livedata/invariant.go:133-137), so the step reads State missing between turns. The audit says the opposite and treats any named owner as held (internal/livedata/audit.go:258). internal-resolve-needs decide, internal-move-card and cmdrd's settle all write this same pattern.
  2. The died and stopped settle paths leave work holderless on purpose. runSettler.diedWith moves the bead to open with no owner (internal/daemon/settle.go:266-279), then adds operator-died. The invariant does not count that label as a holder (invariant.go:122). Its only "holder" is a mail to the Manager. Every settle is also several separate br calls with unheld windows between them (settle.go:566-639).
  3. Births are unheld. internal-create-objective has no owner, wait or plan flag and no holder check (cmd/cmdr/internal_create_objective.go:74-315). workflow plug makes a first step with no owner and no blocker. An empty workstream or track reads "Nothing to do" (internal/livedata/board.go:1042-1049), while the invariant flags it. This is the "#1.4 read Nothing to do 100%" incident.
  4. Gate closes other than approve do not hold what they release. internal-gate pass, rm, apply, an auto gate passing through check, the live gate watcher's gates.SetResult and proposals overrule all close gates without the close door. Only internal-resolve-needs approve runs holdApprovedWork (cmd/cmdr/approval_handoff.go:16-99).
  5. Writes can be lost, not just unchecked. The wait watcher reads the set of running Operators once per poll (internal/daemon/waits.go:286-291). It can then clear an operator: wait that was written mid-poll for a newly spawned Operator, which fits the 15:55 report of a wait that said success and then vanished (§1d).
  6. Spawn has no usage preflight, and its failure paths leave orphans. No spawn or respawn code checks whether the chosen runtime or account has usage left. Usage tracking (NextAccount, MarkOut) lives only in the chat engine (internal/chat/usagelimit.go:81-175). A Codex Operator at 100% exits silently, gets settled as died, and is crash-restarted onto the same pin. internal-operator-provider's failure path sets the task to open and keeps a dead owner (cmd/cmdr/internal_operator_provider.go:150).

Recommendation: add one domain package, internal/holding, made of two parts. The first is a pure Held(row, world) predicate that every reader uses: board, invariant, diagram, stalled list, audit and door. The second is a Transition API that every writer uses: CLI verbs, the app, and cmdrd's own watchers. It runs server-side in the write door, against fresh reads of the affected beads. Every transition names the holder of each bead it touches, or it is refused with the exact command that fixes it. It writes make-before-break: the new holder lands before the old one is removed, as one bd batch where possible. A Manager's name stops counting as a holder. Its durable form is a typed handoff wait such as Manager to plan, Manager dispatch or Manager to recover, which cmdrd already knows how to wake. Section 6 splits this into eight steps that can each ship on their own.

1c. The write door and direct writes

  • Door (internal/beads/door.go:238-251, internal/api/write.go:44-97, internal/api/doorchecks.go): it checks argv-level rules only. These are typed waits, a gate needs an approver and acceptance, Greenlight is approved by the user, a review wait needs pr:, in_progress cannot have owner user, and blocked needs a wait or blocker. It does this only when the request carries COMMANDER_ROLE. Several rules fail open on read errors. It has no holder rule and does not inspect close, reopen, dep, label remove or defer. The client falls back to a direct write when the door is unreachable, and COMMANDER_WRITE_DOOR=off skips it.
  • Direct bd/br: managerguard.BeadsWriteVerb is a deny-list (agentwrite.go:164-226). It misses bd batch, sql, comment, note, tag, priority, link, gate, supersede, duplicate, label propagate, dep relate, the dep A --blocks B shorthand, the maintenance verbs and serve. scripts/br-bd wraps only br; bd is unwrapped. Scripts and non-Bash tools pass both guards.

1d. Lost writes (a write that reports success and then disappears)

The Manager reported this at about 15:55 UTC. Right after internal-spawn-operator, it ran internal-set-objective --waiting operator:<new Operator>. The command printed success, but a minute later the bead had no wait label; running it again landed it. No path rewrites a bead's whole label set: no --set-labels exists outside the door's argument checks, and the spawn path's dispatch cleanup (internal/spawn/approval_handoff.go) removes only named Manager dispatch and handoff-notified: labels. The likely cause is a check-then-act race in cmdrd's wait watcher:

  • waitWatcher captures the set of running Operators once, at the start of a poll (internal/daemon/waits.go:286-291, runningNow). It then lists every project and works through every wait, including GitHub calls, so a poll can take tens of seconds.
  • Take an operator: wait written during that poll, on an Operator spawned after the capture. The watcher judges it against the stale set (waits.go:423-429), decides the Operator "is no longer running", mails [operator] … is no longer running and removes the wait label (wake, waits.go:229-263).
  • The re-read before mailing (FreshShow) confirms only that the label still exists. It does not re-check the fact.
  • To confirm: the Manager's inbox should hold an [operator] operator-op-accept-ty-… is no longer running mail from shortly after 15:55.

The general class is a watcher acting on a fact it read before the write it then undoes. The same shape exists wherever cmdrd clears or moves a holder from a view older than the bead: wait clears in wake, and settle move calls after a slow spawn. The fix is compare-and-clear: a watcher may remove a holder only if the fact it acted on was read after the holder's own since stamp. Otherwise it re-reads the fact and judges again. This is invariant I9 below, and step 6 of the migration.

4. The invariants, stated once

I1 – Every open bead has exactly one current holder, chosen from this closed set:

  1. Operator: a running agent_runs row on the bead (the owner label alone is not enough).
  2. Typed wait: a parseable waiting: label whose waker exists (ci, main-ci, prod-tag, review, operator with a live Operator, an until: time, or a handoff wait addressed to a Manager). An expired time wait stops holding once its wake is delivered and unanswered past the handoff window.
  3. User: an open user gate, or a needs-user card with a stored decision.
  4. Blocker: an open, unparked, non-superseded bead it (or an ancestor) waits on. This holds for any status; "in progress and blocked" is a contradiction the write layer refuses, not a reason to read State missing.
  5. Children: at least one open (non-deferred) child.
  6. Parked: status deferred (with or without a return time).
  7. Gate: a gate bead is held by its stage and approvers.

A Manager's or Commander's name is not a holder. It names who is accountable, not who is moving. A Manager's turn in progress is a display fact ("Manager working"), never what keeps a bead legal.

I2 – Atomic birth. A step, track or workstream is created together with its holder in the same command. A new workstream is born with a Manager to plan handoff wait (reads "Manager planning"), or with its first plan step and that step's holder.

I3 – Make before break. No write removes a holder before the replacement is written. If both cannot go in one transaction, the new holder is written first.

I4 – Closure check. A write is judged on its closure: the bead, its parent chain, its siblings, and every bead that waits on it. Each must satisfy I1 afterwards.

I5 – One reader. Every surface derives "held" and "who holds it" from the same function, on the same inputs. These surfaces are the board line, the diagram lane, the invariant mail, the stalled list, the audit, the door and graph check.

I6 – No silent ending. When a run ends, its bead moves to a named next holder in the same settle: a respawned Operator, Manager to close, or Manager to recover with the reason. It never moves to "open, no owner".

I7 – No unusable start. A spawn or respawn goes only to a runtime/account with usage left; otherwise it is refused with the reason, and the bead stays with its current holder.

I8 – Board never older than a write it answered. After the door answers a write, the snapshot it serves reflects that write. It may be optimistic, but it is never stale.

I9 – No lost writes. An accepted write stays until a later write that knew about it changes it. A watcher that removes a holder must have read the fact it acts on after the holder's since stamp (compare-and-clear).

5. Proposed single guarded domain layer

5a. Shape

internal/holding/            // pure, no I/O
  type Holder struct { Kind Kind; Ref string; Since, Until int64 }   // Operator|Wait|User|Blocker|Children|Parked|Gate
  func Held(b Bead, w World) (Holder, bool, Why)   // the ONE predicate (I1, I5)
  type World interface { RunLive(id) bool; Bead(id) (Bead, bool); Children(id) []string; Blockers(id) []string; Now() int64 }

internal/holding/transition.go
  type Intent interface{ intent() }          // Create, SetState, SetOwner, SetWaits, Close, Park, Unpark, AddDep, RemoveDep,
                                             // GatePass, GateRemove, Place, SettleRun, Respawn, ClearWait, Unwrap ...
  type Plan struct { Ops [][]string; Affected []string; After map[string]Holder }
  func Plan(ctx, w World, in Intent) (Plan, error)   // simulate, run Held on the closure (I4), order writes holder-first (I3)
  type Refusal struct { Bead, Title string; Why Why; Fix []string }   // exact cmdr commands that would make it legal
  • Reads. Held takes a World. The board builds it from the snapshot. The door builds it from FreshDetails of the closure plus spawn.LiveRuns. So the reader and the writer run the same code, and only the source of truth differs: fresh for writes, snapshot for display.
  • Board. leafLine, managerState, idleLine and trackLine call Held first and render by Holder.Kind. "State missing" becomes the rendering of ok == false. Once the writer enforces I1 it is unreachable, and kept only as an alarm. "Nothing to do" is reserved for a closed scope. An open scope with no open children is either held (reads "Manager planning" from its wait) or a violation.
  • Writes. Every verb builds an Intent rather than argv and sends it to cmdrd's door. The door is extended to accept {intent} next to {ops}. The door runs Plan with fresh reads, refuses with Refusal.Fix or applies Plan.Ops (one bd batch when it fits, holder-first otherwise), then patches its snapshot (I8). This happens for every caller: agents, the user, the app's /api/cmd and cmdrd's own watchers. cmdrd calls Plan in-process; it no longer bypasses it.
  • The Manager holder becomes a wait. --owner manager-x on a step that has no other holder is rewritten by Plan into owner plus a typed handoff wait (Manager dispatch, 2 min), or it is refused with that fix. holdApprovedWork already does exactly this, and cmdrd already wakes, receipts and escalates these waits (waits.go:254-258). Three kinds cover every case: Manager to plan (birth), Manager dispatch (released or decided work) and Manager to close / Manager to recover (a run ended).
  • Settle. SettleRun{run, outcome} plans one batch:
    • exited with a report: Manager owner + Manager to close, then remove the Operator owner;
    • died with restart allowed: keep the old owner and add Manager to recover, then the respawn replaces both with the new run (a failed spawn leaves the recover wait);
    • stopped or died for good: Manager to recover: <reason> + operator-died.
    The row then reads "Agent stopped: Manager recovering · 3 min", which is honest and held, rather than State missing.
  • Usage (I7). Plan(Spawn) consults a shared usage.Available(runtime, account). This lifts NextAccount/MarkOut out of internal/chat, and adds Codex's account/rateLimits/updated already captured in chat/usage.json. The result is a refusal or a move to an account with usage left.

5b. What it makes unrepresentable

  • An open bead with no holder after any accepted write, by any caller (I1, I4).
  • A birth without a holder (I2); an empty workstream reading "Nothing to do".
  • A Manager name standing in as a holder (I1).
  • An unheld window inside a single write (I3). Windows between writes vanish too, because each write is checked against its closure.
  • The board disagreeing with the door, the audit or graph check (I5).
  • A board older than an answered write (I8).

5c. What it cannot make impossible (honest limits)

  • A same-UID process that writes Dolt directly (bd sql, bd serve, a script, a raw /api/write with ops). Guards stay speed bumps until the Dolt server has per-role grants. The layer should therefore also keep the invariant watcher as an alarm, now on the shared predicate.
  • Time: a typed wait can be legal when written and expire later. The handoff escalation (receipt, then health issue) covers this; it is a true "Manager's move", not missing state.
  • Process death between batch writes in the non-batchable path (labels, comments). Holder-first ordering bounds the damage to "two holders briefly", which is never illegal.
